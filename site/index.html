Two halves, one idea

Every agent tool writes its conversations to disk in its own shape — JSONL files here, a SQLite database there. That history is yours, it is already local, and no tool will read another's. crossmem is the layer that does.

The CLI — deterministic plumbing

crossmem finds a folder's sessions across every tool, ranks them newest-first, and prints the raw conversation as a Markdown bundle. It decides nothing about meaning. It never guesses, never summarizes, never phones home.

Full command reference →

The skill — the judgment on top

crossmem-loader is a bundled agent skill. It teaches your agent when to reach for crossmem, how to show you the candidate sessions and wait for you to pick, and how to turn a raw transcript into a usable brief.

How the skill works →

The split is deliberate. Summarization policy belongs to the consuming agent, not to a CLI — different agents and different tasks need different amounts of history. The CLI stays the honest source; the skill brings the taste.

Install

Homebrew

brew install muthuishere/tap/crossmem

npm

npm install -g @muthuishere/crossmem

Go

go install github.com/muthuishere/crossmemcli/cmd/crossmem@latest

Then install the agent skill globally, once:

crossmem install --skills

Lands in ~/.claude/skills/crossmem-loader, and ~/.agents/skills/crossmem-loader when codex is on PATH. Global only, by design — crossmem is a cross-repo layer, not a per-repo one.

The hot path

With the skill installed, you just say “resume” and your agent runs this. By hand, it is three commands.

  1. See what exists for this folder 
    crossmem list . --limit 5

    Each row is the agent, how long ago it ran, and — the part that actually distinguishes two sessions in one folder — the first and last thing you asked. The first question is the goal; the last is where the work stopped. Tool output is skipped when picking them, because agents record their own shell results as user turns.

    1. claude · 15 hours ago · export conversations as q&a
2. codex  · 2 days ago   · windows store paths
  2. Load the one you picked 
    crossmem load --session <ref> --full

    The ref is the handle from list — a transcript path, or devin:<id> / opencode:<id> / copilot-cli:<id>. Loading is identical whether that session lived in a JSONL file or a SQLite database.

  3. Persist it so nobody pays twice 
    crossmem update .

    Writes a committable .crossmem/ — context.md, guardrails.md, sessions.json, sources.json. Idempotent: no generated-at timestamp, unchanged files left untouched, so re-running makes no diff and no spurious commit.

Four decisions worth knowing

Guardrails ≠ history

Repo instruction files (AGENTS.md, CLAUDE.md) are marked authoritative. Transcripts are context only — what happened, never what you must do. When a transcript contradicts a guardrail, the guardrail wins, and the bundle says so out loud.

It matches by real cwd

A session maps to a folder by the working directory recorded inside its transcript — not by a name guess. Dashes in folder names, relocated configs, encoded project dirs: all handled.

Worktrees are the same repo

An agent works one worktree per task, but the context often lives in the main checkout. A folder also matches its repo's other worktrees — read from git's own files, so no git binary is needed. --no-worktrees opts out.

Your live session is excluded

load . means the previous session, not a mirror of the conversation you're already in. Detected automatically for Claude Code, Codex and the Devin CLI; CROSSMEM_CURRENT_SESSION covers the rest.

Read-safety is a contract, not a promise

This tool reads other tools' private stores, so the boundary is written into the code and the docs both:

  • Credential files, auth databases, *.env and vault/ directories are never read — Devin's credentials.toml sits right next to the session DB and is deliberately skipped.
  • The same filter applies to dumps, so a sync pushed to a remote cannot carry a secret value.
  • export writes a nameless corpus: no agent name, no model name, no tokens.
  • No telemetry. Every operation is a local read. Debug logging is opt-in (CROSSMEM_DEBUG=1) and never logs transcript contents.

Also a Go library

pkg/crossmem is the same engine the CLI runs, with no process-global state — so a Go agent orchestrator can link it instead of shelling out to whatever crossmem is on PATH.

c, err := crossmem.New(crossmem.Options{})
sessions, err := c.List(ctx, crossmem.ListOptions{CWD: root, Limit: 5})
tr, err := c.Transcript(ctx, sessions[0].Ref)
md, err := c.Load(ctx, sessions[0].Ref, crossmem.LoadFull)
rules, err := c.Guardrails(root)

Semver from v0.2.0; the JSON field names of Session, Store, QARecord, Transcript and Event are frozen. Go reference · ADR 3.
