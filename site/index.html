crossmem Install Resume Stores Library Design GitHub

Your agent context, portable.

You hit a usage limit in one tool and reopen the folder in another — and re-explain everything. crossmem reads the local session stores of Claude Code, Codex, Devin, Copilot and OpenCode, and emits one clean Markdown bundle the next agent can load. Local reads only. No telemetry.

Resume across tools

One tool runs out, you reopen the same folder in another, and pick up where you left off.

# 1. Load this folder's latest session (summary by default)
crossmem load . --limit 1

# 2. Prefer to choose? List recent sessions for THIS folder, newest first
crossmem list . --limit 5
#   2026-06-29T14:27  codex   ~/.codex/sessions/.../rollout-….jsonl
#   2026-06-29T04:10  devin   devin:narrow-action
#   2026-06-28T21:02  claude  ~/.claude/projects/.../<id>.jsonl

# 3. Load the one you picked, by its handle
crossmem load --session <handle>
crossmem load --session <handle> --full

list shows each session's title plus the first and last thing you asked — a title says what a session was called, the questions say what it became. Tool output is skipped when picking them.

The session you are running inside is excluded by default, so load . means the previous session rather than handing your live conversation back to you. --include-current overrides it; CROSSMEM_CURRENT_SESSION covers tools that export no session id.

Matches by real cwd

Sessions map to folders by the working directory recorded in the transcript — dashes in folder names and all.

Worktree aware

A worktree also matches the main checkout and its siblings, read from git's own files. No git binary needed.

Guardrails vs history

Repo instruction files are marked authoritative; transcripts are context only. The bundle says so out loud.

Never reads secrets

Credential files, auth DBs, *.env and vault/ are excluded by contract — including from dumps.

Everyday commands

crossmem scan                                  # discover known local context stores
crossmem list . --limit 5                      # recent sessions for THIS folder
crossmem list --provider claude --limit 20     # recent Claude sessions everywhere
crossmem load .                                # context bundle for this repo
crossmem update .                              # write durable .crossmem/ files (idempotent)
crossmem export .                              # write .crossmem/qa.jsonl for this folder
crossmem import . --in ~/conversations         # import qa.jsonl into this folder
crossmem sync --remote hetzbox:companydata/convdump   # push a store dump with rclone
crossmem config                                # where it looks, and what it found

crossmem update . writes .crossmem/context.md, guardrails.md, sessions.json and sources.json — the durable, committable form of a bundle. It carries no generated-at timestamp, so re-running produces no diff.

export / import

export writes one qa.jsonl of every question, the full answer, and the tools and results in between — no agent name, no model name, no tokens.

{"sessionId":"…","folder":"/path","q":"…","a":"…","time":"…",
 "messages":[{"role":"user","content":"…"},{"role":"tool","name":"Write","content":"…"}]}

Every store lists all of its OS-specific candidates. $CLAUDE_CONFIG_DIR, $CODEX_HOME, $DEVIN_HOME and $DEVIN_DB_PATH win when set. Run crossmem config for the exact list on your machine.

Point it somewhere else

// ~/.config/crossmemcli/config.json
{
  "stores":      { "devin:sqlite-sessions": "D:/agents/devin/cli/sessions.db" },
  "extraStores": { "opencode": "~/other/opencode/opencode*.db" },
  "defaults":    { "mode": "full", "limit": 5 }
}

stores replaces a store's built-in locations, extraStores adds to them. ~, %VAR%, $VAR and globs expand; a path whose variable is unset is skipped, so one config file works on every machine. crossmem config --init writes a starter.

Use it as a Go library

pkg/crossmem is the same engine the CLI runs, with no process-global state.

go get github.com/muthuishere/crossmemcli@latest
c, err := crossmem.New(crossmem.Options{})
sessions, err := c.List(ctx, crossmem.ListOptions{CWD: root, Limit: 5})
tr, err := c.Transcript(ctx, sessions[0].Ref)
md, err := c.Load(ctx, sessions[0].Ref, crossmem.LoadFull)
rules, err := c.Guardrails(root)

Semver from v0.2.0; the JSON field names of Session, Store, QARecord, Transcript and Event are frozen. Runnable example: go run ./examples/list <folder>.

Agent skill

Optional global skill activation, so an agent reaches for crossmem on its own when you say “resume”:

crossmem install --skills      # ~/.claude/skills/ and ~/.agents/skills/
crossmem uninstall --skills

Global only, by design — crossmem is a cross-repo context layer, not a per-repo one.
